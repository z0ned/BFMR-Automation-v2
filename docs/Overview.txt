BFMR AUTOMATION V2 — OVERVIEW (21 OCTOBER 2026)

CURRENT REFERENCES
Start with README.md, docs/BFMR_Solution_Design_Specification_v22.md,
docs/BFMR_Implementation_v22..md and AGENTS.md. OPEN_ISSUES.md tracks unfinished
work; RELATIONAL_INTEGRATION.md and database/README.md describe persistence,
configuration and controlled cutover.

RUNTIME
Node.js/TypeScript command-line scripts process authenticated Gmail new-deal
messages, create and verify exact BFMR reservations, evaluate supplier evidence,
and run the approved Amazon quantity-one workflow under its financial and
checkout safeguards. Tracking and BFMR reconciliation run through the active
worker. Provider contracts and supervised production acceptance remain gates.

PERSISTENCE
The canonical business schema and upgrades live under database/. Relational
repositories store reservations, orders, shipments, payments and evidence.
Private Gmail, batch/recovery and status/notification journals remain explicit
operational stores. The separate orchestration engine retains its existing
compatibility store. Database transactions do not include external actions.

SAFETY AND REMAINING WORK
Use exact account, deal, reservation, order and tracking identity. Unknown
outcomes stop for reconciliation; never replay a possibly completed action.
Single-deal automatic purchasing and the 14-day latest-delivery cutoff remain
unfinished. Follow OPEN_ISSUES.md for provider, database, recovery and service
acceptance. No document or sample grants live action authority.
